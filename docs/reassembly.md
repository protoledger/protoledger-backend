# Сборка потоков TCP: правила и проверки

Поток направления собирается по sequence numbers (RFC 9293, сравнение по модулю 2^32). Дыры и неоднозначности не заполняются: в потоке они остаются участками метаданных, а не байтами.

## Политики проекта

Хранятся в `project.yaml`, меняются `PATCH /api/project/settings`; после смены записи собираются заново. Результаты прогонов подписаны настройками, поэтому устаревшие отличимы от актуальных.

| Настройка | Значение | Что делает |
|---|---|---|
| `overlapPolicy` | `first` (по умолчанию) | При перекрытии с различающимися байтами принимаются байты более раннего сегмента |
| | `last` | Принимаются байты более позднего сегмента |
| | `flag` | Ни один вариант не принимается: участок неоднозначен, принятых байтов нет |
| `checksumPolicy` | `warn` (по умолчанию) | Сегменты с неверной суммой учитываются, замечание в диагностике и значок у соединения |
| | `ignore` | Сумма не проверяется и не отмечается |
| | `drop` | Сегменты с неверной суммой не участвуют в потоке |

При любой политике перекрытия неоднозначность видна: у участка перечислены все варианты байтов и кадры, их давшие. Диагностика `bad_checksum` называет узел, если неверны суммы всех его сегментов, а у остальных узлов верны: это похоже на offloading при захвате на этом узле. Иначе — повреждение по пути.

## Ситуации ТЗ 7.3 и где они проверены

| | Ситуация | Поведение | Проверка |
|---|---|---|---|
| D1 | Переупорядочивание | Порядок по seq, в том числе через переход 2^32 | `reorder`, `reorder_and_duplicates_do_not_change_stream`, сверка с tshark |
| D2 | Одинаковый повтор | Байты один раз, все кадры-источники сохранены, у повтора признак `duplicate` | `duplicates`, сверка с tshark |
| D3 | Пропуск и усечение | Участок `gap` фиксированной длины, нулей нет | `gap-truncation`, злой корпус `tcp-seq-jump-1gib` |
| D4 | Перекрытие с разными байтами | Неоднозначный участок, варианты с кадрами, политика `first`/`last`/`flag` | `overlap-conflict`, `flag_policy_keeps_ambiguity_without_choosing`, `overlap_policy_changes_what_is_accepted…` |
| D5 | Нет начала соединения | Роли `unknown`, начало потока недоступно | `no-handshake` |
| D6 | Контрольные суммы | Явная политика, учёт offloading | `bad-checksum`, `checksum_report_tells_offloading_from_corruption`, `checksum_policy_drop_removes_bad_segments` |
| D7 | Повтор портов, повторный импорт, изоляция ошибок | Разные соединения; повторный импорт — отдельный импорт без склейки; ошибка записи не мешает остальным; время — время захвата кадров | `port-reuse`, `reimport_is_a_new_import…`, `every_hostile_file_is_handled…` |
| D8 | Неподдерживаемое | Диагностика: другой канальный уровень, IPv6, фрагменты, не-TCP | `background`, злой корпус |

## Сверка с tshark

`crates/pl-reassembly/tests/tshark.rs` сравнивает собранные байты каждого направления с `tshark -z follow,tcp,raw` для записей без дефектов (порядок, повторы, неверные суммы, длинные ответы). В CI tshark ставится и тест обязателен (`PL_REQUIRE_TSHARK=1`); локально без tshark тест пропускается.
