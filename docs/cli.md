# Командная строка

Тот же движок, что и в интерфейсе, без браузера: повторное применение описания к новым записям и перепроверка проекта. Результат детерминирован (без времени выполнения): повторный запуск даёт тот же вывод.

Коды возврата: **0** — всё совпало, **1** — есть отличия, **2** — ошибка (текст на стандартном потоке ошибок).

## apply — интерпретация к записям

```bash
protoledger apply --interpretation spec.yaml --input new.pcapng [--input second.pcap …] \
  [--action-log log.csv --mapping mapping.yaml] [--overlap first|last|flag] [--checksum ignore|warn|drop] \
  [--out result.json] [--strict]
```

Проект не нужен. Записи собираются по тем же правилам, что в интерфейсе (политики по умолчанию — `first` и `warn`), интерпретация применяется ко всем потокам в области применимости. В JSON: версия формата `protoledger/apply-result@1`, digest интерпретации, политики, сводка по категориям (`matched`, `violated`, `incomplete`, `ambiguous`, `unmatched`, `limit_exceeded`), для каждой записи — диагностика захвата и потоки с сообщениями: поля со статусами знания (`rule`, `hypothesis`, `unknown`), нарушения, неописанные байты. Длинные значения (больше 256 байт) усечены, `valueTruncated: true`, полная длина — в `len`.

Если передан журнал действий (`--action-log` + `--mapping`, колонки сопоставляются так же, как в API), гипотезы интерпретации с `test` проверяются на нём: в результате `hypotheses` — выполнилась ли на k из n применимых примеров, контрпримеры с якорями.

Без `--out` результат идёт в стандартный вывод, краткая сводка — в stderr. `--strict`: код 1, если есть сообщения не в категории `matched`.

Эталонные результаты на записях стенда лежат в `fixtures/stand/expected/`; тест сверяет с ними вывод `apply` (`BLESS=1 cargo test -p protoledger --test cli` обновляет после проверки глазами).

## verify — перепроверка проекта

```bash
protoledger verify my-research.protoledger [--run run-0001]
```

1. Копии записей в `sources/` сверяются с sha256 (изменена — отличие).
2. Каждый сохранённый прогон (или указанный) выполняется заново на тех же входах — ревизия интерпретации, фильтры корпуса, записи — и сравнивается с сохранённым: сводка, таблицы сообщений, контрпримеры. Совпало — `результат воспроизводится`, иначе показано, что изменилось; если настройки сборки потоков изменены после прогона, это указано отдельно.

Проект можно скопировать в другую папку и проверить там: пути внутри проекта только относительные.
