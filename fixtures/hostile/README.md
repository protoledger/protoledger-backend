# Злые записи

Намеренно кривые файлы для проверки устойчивости разборщиков. Сгенерированы `pl-hostile`, руками не править — тест `committed_files_are_up_to_date` сверяет их с генератором.

```bash
cargo run -p pl-hostile -- --out fixtures/hostile              # перегенерировать
cargo run -p pl-hostile -- --out /tmp/large --large            # крупные записи (в репозиторий не кладём)
BLESS=1 cargo test -p pl-hostile --test hostile hostile_samples # обновить expected.json (результат просмотреть глазами)
FUZZ_ITERATIONS=200000 cargo test -p pl-hostile --release mutated_real   # длинный прогон мутаций
```

`expected.json` — итог разбора каждого файла: либо ошибка (`not_capture`, `limit_exceeded`), либо число кадров, сегментов, соединений, самый длинный поток, байты дыр и диагностика по кадрам. Тесты проверяют:

- `pl-hostile` — конвейер `pl-capture` → `pl-reassembly`: без паник и зависаний, итог совпадает с эталоном, заявленные «4 ГиБ» и скачки seq не выделяют память, 100 тысяч соединений даёт `limit_exceeded`, 100 тысяч сегментов по байту собираются за разумное время;
- мутации настоящих записей (случайные порчи, обрезка, вставки) не роняют разбор;
- `pl-server` — каждый файл через `POST /api/sources`: задача завершается, ошибки — `413` или `422` с текстом, сервер продолжает отвечать, байты потоков читаются.

| Группа | Файлы |
|---|---|
| Не запись | `empty`, `text`, `png-as-pcap`, `pcap-header-cut` |
| Контейнер pcap | `pcap-no-packets`, `pcap-last-record-cut`, `pcap-caplen-huge`, `pcap-caplen-over-snaplen`, `pcap-snaplen-zero`, `pcap-zero-length-frames`, `pcap-unknown-linktype`, `pcap-timestamps-wild` |
| Контейнер pcapng | `pcapng-block-length-{zero,huge,unaligned}`, `pcapng-epb-without-idb`, `pcapng-unknown-linktype`, `pcapng-captured-len-lies`, `pcapng-trailing-garbage`, `pcapng-two-shb` |
| Канальный уровень без Ethernet | `linktype-cooked-broken` (Linux cooked), `linktype-loopback-families`, `linktype-raw-not-ip`: обрезанные заголовки, чужой протокол, IPv6 — рядом с одним исправным кадром |
| Заголовки IPv4/TCP/Ethernet | `ipv4-ihl-*`, `ipv4-total-length-*`, `ipv4-version-6-in-ipv4-frame`, `tcp-offset-*`, `tcp-all-flags`, `ethernet-runt`, `ethernet-truncated-ip` |
| Поведение TCP | `tcp-seq-jump-1gib` (дыра как метаданные), `tcp-seq-jump-2gib` (ровно 2^31 — «старые» данные по RFC 9293, сегменты не учитываются), `tcp-seq-wrap`, `tcp-overlap-storm`, `tcp-many-connections`, `tcp-data-after-rst` |
| Содержимое | `payload-hostile-strings`: HTML, JS, управляющие символы и RTL в потоке — везде показывать как текст |

## Журналы, описания протокола, манифесты проекта

Чужой проект, журнал действий и описание протокола — такой же недоверенный ввод, как запись. Образцы лежат в подкаталогах, итог разбора каждого — в `inputs.expected.json`:

```bash
BLESS=1 cargo test -p pl-hostile --test inputs    # обновить файлы и эталон (результат просмотреть глазами)
```

| Каталог | Что внутри | Что проверяется |
|---|---|---|
| `journals/` | пустой файл и только заголовок; BOM и CRLF; байты не в UTF-8; нет колонки времени; незакрытая кавычка; строки разной длины; «формулы» табличных редакторов; HTML и управляющие символы; числа за пределами 128 бит; ключ на 64 КиБ; JSON с вложенностью 10 тысяч, с 5 тысячами ключей, оборванный | `pl-actions`: журнал разобран (с перечнем строк, которые не разобрались) или отклонён с причиной; строки остаются данными |
| `interpretations/` | якоря и ссылки YAML («миллиард смеха»), вложенность 10 тысяч, неизвестные ключи, версия формата из будущего, нулевой размер и пустой разделитель, смещения и длины на границе 32 и 64 бит, повторяющаяся группа на 4 млрд элементов, выражения-бомбы (скобки, длина, переполнение, деление на ноль), HTML в текстах | `pl-interp`: описание отклонено с причиной либо принято и применено к потоку за разумное время, без гигантских выделений |
| `projects/<имя>/project.yaml` | манифесты: вместо sha256 записи, журнала и ревизии — путь наружу или абсолютный путь; идентификатор прогона — путь; дубли импортов; пропуск в номерах ревизий; формат из будущего; якоря YAML; неизвестные поля | `pl-project`: проект не открывается либо открывается и ни одна операция чтения не выходит за пределы папки |

Тесты (`crates/pl-hostile/tests/inputs.rs`) дополнительно строят на лету: журнал на строку больше предела в миллион строк, поле на 64 МиБ, описание и манифест больше 4 МиБ, подменённую копию записи (другая правильная запись под тем же именем — «повреждена») и каталог `sources/`, заменённый символической ссылкой наружу. Через API (`pl-server`, тест `hostile_journals_and_descriptions_never_break_the_server`) каждый журнал и каждое описание дают успех или ошибку `413`/`422` с текстом, сервер продолжает отвечать.

Пределы журнала: файл 256 МиБ, 1 млн строк, поле 64 КиБ, 256 колонок, вложенность JSON в ячейке 16, значений в ней 1024.
