# Фаззинг

Цели `cargo fuzz` для всего, что разбирает недоверенный ввод. Падение, зависание дольше 20 секунд или рост памяти выше 2 ГиБ — дефект.

| Цель | Что проверяет |
|---|---|
| `capture` | чтение pcap и pcapng, сборка TCP-потоков при всех политиках; инварианты карты участков |
| `journal` | журнал действий: CSV, пары «ключ=значение» и JSON в ячейках, все форматы времени |
| `interpretation` | описание протокола из YAML: разбор, проверка, применение к потоку с дырой |
| `expr` | язык выражений: разбор и вычисление |
| `framing` | все виды фрейминга и разбор полей на произвольных байтах с дырой и неоднозначным участком |

Нужны Linux, nightly-компилятор и `cargo install cargo-fuzz`:

```bash
cargo +nightly fuzz run capture -- -max_total_time=150 -max_len=65536 -rss_limit_mb=2048 -timeout=20
```

В CI (workflow `fuzz`) цели запускаются раз в сутки и вручную, по 150 секунд на цель; начальный корпус собирается из `fixtures/` (злые и синтетические записи, журналы, описания). В запросах на изменение, которые трогают цели, — короткий прогон. Найденный вход сохраняется артефактом прогона; после исправления его стоит добавить в `fixtures/hostile` с ожидаемым итогом.
